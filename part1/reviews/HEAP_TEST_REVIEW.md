# Ревью BinaryMaxHeapTests

Исходный набор обширный: 95 тестовых случаев, в том числе 5 обращений к отсутствующей min-heap. Проверены конструкторы, ёмкость, Count/IsEmpty, Add, Peek, RemoveMax/ExtractMax, Clear, RebuildHeap, индексы, Initialize, копии ToArray/ToList, Union, reverse comparer и его вызовы. Есть детерминированные случайные данные с seed, дубликаты и проверка инварианта при Add/Extract. Нельзя писать, что этих сценариев вообще не было.

Но выполнение всех строк/ветвей не означает проверку всех значимых состояний: условие в индексаторе уже проходилось в обе стороны, а нарушение внутреннего ребра оставалось незамеченным. Исходный Initialize(empty) тест прямо требовал сохранять старые данные, хотя IMaxHeap.Initialize документирован как замена текущей кучи.

## Дополнение: 11 новых тестовых случаев

| Новый тест | Что ранее не проверялось |
|---|---|
| Indexer_IncreaseBelowRoot_MovesAboveSmallerParent | Внутренний узел пересекает родителя без изменения максимума |
| Indexer_DecreaseInternalNode_MovesBelowLargerChildren | Уменьшение узла и отношения со всеми потомками |
| Initialize_Null_ThrowsArgumentNullAndPreservesPreviousState | Null collection и атомарность проверки входа |
| Initialize_RepeatedIncludingEmpty_AlwaysReplacesState | Много переинициализаций, пустая замена непустой кучи, Add после неё |
| MixedOperations_AgreeWithMultisetAfterEveryStep(false/true) | Add → set → Extract → Add и опустошение/повторное Add, обычный и reverse comparer, инвариант и все элементы после каждого шага |
| EqualPriorityItems_AreAllPreservedWithoutAssumingStableOrder | Разные объекты одного приоритета: не теряются, стабильность порядка не требуется |
| NullElements_DefaultReferenceComparerOrdersAndPreservesThem | Null reference элементы разрешены хранилищем и default comparer; сохраняется кратность |
| Union_AliasedInputs_CurrentDestructivePolicyConsumesObjectOnce(false/true) | Две переменные на один объект и одна переменная как оба ref-аргумента |
| Union_CustomComparers_CurrentPolicyUsesDefaultInResult | Две reverse кучи, результат сортируется default, все элементы и повторы сохранены |

Базовые свойства проверяются существующими и новыми тестами совместно: корень — максимум; parent >= child по используемому comparer; сохранность multiset; дубликаты; упорядоченное извлечение; пустая/одноэлементная куча; недопустимые индексы; обычная/пустая/repeated Initialize; set вверх/вниз относительно родителя и детей; Union обычных/пустых/alias/custom куч. Инвариант проверяется через публичную копию ToArray, без reflection или доступа к private-полям. MixedOperations сверяется с независимой моделью List + сортировка и кратностями после каждого изменения.

Оставшиеся границы контракта: Clear(empty) и Peek/Extract(empty) бросают общий Exception, что уже закреплено исходными тестами. Менять типы исключений без отдельного требования не нужно. Производительность Add/set O(n) из-за полного rebuild сохранена в пользу минимального исправления; sift-up/down O(log n) — возможное отдельное улучшение. Getter пропускает index==Count до ArrayList, но публично тот же IndexOutOfRangeException, поэтому это избыточно слабый guard, а не наблюдаемый дефект. CSV для PrimesList отсутствует, но куча этот helper не вызывает, поэтому нет основания удалять или чинить его в рамках задания.
