# Реальные smoke-тесты curl

Процесс: `ASPNETCORE_ENVIRONMENT=Development ASPNETCORE_URLS=http://127.0.0.1:5087 Database__Path=... dotnet run --project src/Subscriptions.Api --no-build`.

Это настоящий Kestrel/SQLite, не WebApplicationFactory. Источник: scripts/smoke.py запускает **curl** для каждого HTTP-запроса; конфигурация с credentials/Bearer передаётся stdin `curl --config -`, чтобы не сохранять секреты в argv/файлах. Ответы захватываются реально и сохраняются с явной маскировкой password/access/refresh/reset. HTTP-коды, headers/correlation, ID и business JSON не подделывались. В сохранённых командах `[REDACTED]` — маска, а не пригодный пароль; для повторения запускать script, который создаёт собственные credentials в памяти.

Первый smoke: artifacts/12-smoke/summary.json, run.log и31 отдельных JSON. Последний smoke после чистой сборки: artifacts/final/smoke/summary.json и curl-таблица ниже (появляется после финальной проверки). Среди assertions: replay body/id тот же, exact expense RUB10, после void RUB0, forecast содержит active subscription, foreign404. Swagger UI дополнительно проверен отдельным curl; OpenAPI JSON проверяется31-м запросом, schemas/auth также API-тестом.

F03–F05 проверены unit/API, но не выдаются за curl-smoke в этой таблице. Reset email sender доступен только через DI теста, публичного inbox нет. Фактические результаты и команды:
